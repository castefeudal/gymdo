# r75 verification record

Supersedes the incomplete r74 increment. Work continues on the same PR and original
data-safe source/build pipeline. Local-first behavior and 1,324 exercises remain.

Implemented: label-based food catalog and meal diary; servings/grams; favorites;
saved meals/repeat/edit; day/week/month totals and coverage; explicit completed-day
analytics; schema-v12 full backups; local PDF extraction and Russian/English OCR
with manual review; separate calculated free testosterone; laboratory charts with
assay/unit separation and exact tables; bundled Inter variable Latin/Cyrillic.

Fonts use the SIL Open Font License. PDF.js and Tesseract are bundled from pinned
npm lockfile versions. OCR language models are checked in; no CDN or upload endpoint
is used during document processing. Optional PDF/OCR dependencies load on request,
outside the initial application graph. See the component license files in assets.

The old 480 KB cap is retained for the initial static JS graph (measured 445,198 B).
The complete boot graph, including dynamically imported initialization modules,
is measured and checked against the same 480 KB limit (476,540 B). Only the static
core and its small loader receive early hints; other domain imports retain their
normal priorities. Generated boot CSS/JS and safe HTML attributes are minified
to preserve the existing 10 KB document budget.
The complete application cap grows to 520 KB raw /175 KB gzip to account explicitly
for the new lazy food/report views and validators (measured 515,286 B total).
Large optional PDF/OCR assets are separate, never part of boot or install precache.
CSS has an explicit 276 KB /49 KB gzip cap for the new report/food controls
(previously 272 KB /48.5 KB). No existing budget is silently disabled. Production measurements and CI results will be recorded with
the release revision; local results do not certify the deployed site.

188 unit tests pass, including calendar month/week boundaries, independent food
snapshots, atomic backup validation, conservative PDF suggestions, assay separation
and the published ISSAM example. Local feature browser checks exercise real PDF,
real OCR image, meal logging and accessible controls in four browser configurations.

Text startup optimization preserves normalization and transliteration for every
authored catalog/content string, the complete RU/EN exercise-name sort order and
date labels across five timezones and DST boundaries. The common RU/EN path avoids
costly Unicode-property matching; other scripts keep the original behavior.
The local, instrumented 4x-CPU diagnostic reduced data preparation from about
514ms to 241–276ms. This is diagnostic evidence, not a production Lighthouse gain.
Offline worker registration begins after the first UI paint, with a bounded
250ms fallback for background tabs whose animation frames may be suspended.

Public WebKit verification exposed a delayed route-heading focus that could steal
focus during search entry. Heading focus is now completed synchronously with the
route change. Search state/URL commit immediately; only rendering is debounced,
so pending work cannot resurrect a cleared or Back-restored query. Eight browser
regressions failed on the previous implementation and pass after the fix across
Chromium desktop/mobile, Firefox and WebKit. Diagnostic exercise count now reads
the current lazily loaded catalog instead of an initial zero snapshot.

At 901–1399 CSS pixels, the header uses separate brand/control and navigation
rows, retaining the authored labels and readable font sizes. A four-engine
geometry check covers 13 intermediate widths, RU/EN and balanced/large reading
settings; it checks actual CSS viewport bounds, including Windows WebKit at 125%
device scaling. Both calculators and laboratory records are reachable from the
mobile More screen. The [reviewed medium-width header](r75/medium-header.png)
shows all navigation labels, language controls and command search within bounds.

The journal lifecycle checks pass 20/20 across Chromium desktop/mobile, Firefox
and WebKit: repeated RU/EN switches preserve draft values, units and dates; failed
durable writes retain the draft for a single-record retry; obsolete event handlers
are cancelled. Four additional browser checks verify complete contained exercise
previews at 320px and pagination from 12 to 24 of all 1,324 exercises.

No self-assigned independent design score, formal WCAG certification, or field
INP/p75 is claimed. Original low-resolution GIFs remain honestly labeled; the HD
player accepts provenance-checked licensed video without inventing redistribution
rights for 1,324 third-party assets.

The 1.86 MB authored exercise source is preserved. A deterministic build emits a
184,789-byte light catalog and a separate instruction map. A reconstruction test
proves exact equality for all 1,324 records. Instructions load before opening an
exercise or Run Mode and both generated resources are included in offline cache.
New-user Today no longer parses/renders hidden exercise data; command search and
exercise routes load it on demand. Hidden main/footer layout is deferred until
readiness, then all controls and accessible names are restored before boot ends.
