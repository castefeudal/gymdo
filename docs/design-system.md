# MARKOV MADE GYM design system

## Identity

The mark is a geometric M built from two mirrored halves split on the centre axis: the left half is the text colour, the right half is the performance accent. It reads at 24 px, needs no plate for small sizes, and is used directly as the app icon plate, the favicon and the OG composition. Brand sources live in `assets/brand/` (`mark*.svg`, `lockup*.svg`, `favicon.svg`, PWA icons, `og-image.png`); `scripts/brand-assets.mjs` regenerates the vector sources and the raster pages that `scripts/brand-render.mjs` captures.

## Palette

One semantic palette owns three themes. Obsidian is graphite (`#080C11` canvas, `#101720` surface, `#17212B` elevated) with a lime performance accent (`#BEF47D`, ink `#0A1503`) and a cool analytics accent (`#8BBFD1`). Soft is the neutral light theme (`#EEF1F3`), Ivory the warm paper theme (`#F4F2EC`); both darken the accent to `#3F7A18` / `#4C6A1E` so lime never carries white text. Components read semantic tokens only — `tokens.css` owns colour, geometry, spacing and motion.

The interface follows Today → start → complete → save → progress → next action. Desktop shows seven product sections (Сегодня · Тренировки · Упражнения · Питание · Прогресс · Инструменты · Ещё) in one header row; phones use a five-tab bottom bar with the remaining sections behind «Ещё», plus contextual training controls. Home keeps one primary action on the next-action card; the context bar never repeats it. Accent indicates actions and active states. Panels share geometry across Obsidian, Soft and Ivory.

## Ownership

Author CSS in styles/source/: tokens, foundation, shell and feature files. app.css is generated by scripts/build-styles.mjs; never edit it directly. No additional production override stylesheet is loaded. tokens.css owns semantic colors, geometry, spacing and motion. Components read semantic tokens.

Sequence comments preserve source order while compatibility selectors are divided between owners. Each top-level rule needs a unique @sequence marker. Modify the existing owning rule; do not append a presentation layer. The builder rejects missing/duplicate markers and strips them from production.

## Interaction and readability

Use visible labels, semantic buttons, keyboard focus and meaningful disabled states. Labels are at least 14px; reading copy is 16px. Values use tabular numerals. Primary touch controls are at least 44px. Run Mode shows large load/reps, the active set, secondary fields inside Details and sticky completion/rest actions.

Exercise media uses contain sizing. Technique separates steps, cues, mistakes, breathing, range, muscles, equipment and substitutions. Charts precede supplementary statistics; empty metrics are omitted. Calculator method metadata, ranges and limitations remain available.

## Verification

Visual comparison covers 360×800, 390×844, 430×932, 768×1024, 1440×900 and 1920×1080 in all themes. Baselines cover nine main routes plus exercise detail, Run Mode, filters, command palette, empty/offline and loading/error states. Screenshots disable animation only during capture; production exercise animation remains available.

Axe checks serious/critical violations. E2E checks keyboard focus containment/return, overflow and persistence. Respect prefers-reduced-motion; motion must never carry essential information.

Progress axis labels are checked in screen pixels after SVG scaling (at least 14px), including a desktop-to-phone resize. Sparse observations show a collection action before supplementary metrics instead of a premature plan adjustment.
